一分钟上手页面里的每一步都可以直接点
框架在页面加载完成后把 当前窗口专属的 window.WindowApi 注入进来。 不带 key 的方法都作用于当前窗口；需要操作别的窗口时，把它的 controllerKey 传给 xxxByControllerKey(...)。 本页打开的每个子窗口都持有自己独立的 WindowApi，所以同一段代码在父窗口执行和子窗口执行的效果不同。 
// 1. 必须等框架通知就绪（框架会在注入完成后调用一次）
window['$$_apiReady'] = function () {

    // 2. 当前窗口信息；主窗口的 key 是 null（不是空串）
    var key       = WindowApi.getKey();
    var parentKey = WindowApi.getParentKey();
    var status    = WindowApi.getStatus();        // 例如 OPENED(已打开)

    // 3. 打开子窗口（父窗口自动取当前窗口）
    var childKey = WindowApi.createChildScene('web/windowapi-demo.html', 900, 680);

    // 4. 改标题 / 尺寸 / 状态
    WindowApi.setTitle('我的窗口');
    WindowApi.setSize(1000, 700);
    WindowApi.setMaximized(true);

    // 5. 跨窗口操作：key 为 null 时表示主窗口
    WindowApi.setTitleByControllerKey(key, '子窗口标题');
    WindowApi.minimizeWindowByControllerKey(null);   // 最小化主窗口

    // 6. 给子窗口发 JS 回调（子窗口里定义 window.onParentMessage）
    WindowApi.onCallByControllerKey(childKey, 'onParentMessage');
};
提示：WindowApi 是完整 Java 对象，JS 能调用它的全部 public 方法； 只应把它注入给随应用打包的可信页面，不要用它加载远程/用户提供的 HTML。

快捷体验不用切页，先感受一下
模态窗口会阻塞它所拥有的窗口：WINDOW_MODAL 只阻塞 owner（这里是当前窗口）， APPLICATION_MODAL 阻塞应用内全部窗口。非模态窗口不阻塞任何窗口。
先分清"当前窗口"和"指定窗口"
  • 无 key 参数：getTitle()、setWidth(...)、minimizeWindow() —— 只操作加载本页的窗口。
  • 带 key 参数：getTitleByControllerKey(key)、setWidthByControllerKey(key, w) —— 操作指定窗口。
  • 只有 null 表示主窗口；空串 "" 或未知 key 都算"找不到窗口"（getter 返回 null、setter 返回 false）。
  • 每个窗口的 WindowApi 都是独立实例，所以子窗口里的 getKey() 返回子窗口自己的 key。
  • getChildKeys() / getAllKeys() 返回 String[]；元素是 Java String 包装对象，比较/序列化前请用 String(keys[i])。
// String[] 的安全用法
var raw = WindowApi.getChildKeys();
var keys = [];
for (var i = 0; i < raw.length; i++) {
    keys.push(String(raw[i]));       // 不要直接 raw[i] === 'xxx'
}
// keys 现在是普通 JS 字符串数组，可以 join / 比较 / JSON.stringify
属性读写全部作用于当前窗口
读方法在窗口不可用时返回安全默认值（0 / false / null），不会抛 NPE； 写方法会校验参数（宽度必须 > 0，最小尺寸允许 0，透明度自动截断到 0~1），非法值只记日志、不生效。
显示状态与窗口控制最小化 / 最大化 / 全屏 / 置顶 / 关闭
minimizeWindow() 是最小化到任务栏，restoreWindow() 恢复并聚焦； hiddenWindow() 是旧名字，行为等同 minimizeWindow()。 关闭窗口有两个版本：closeWindow() 强制关闭；requestCloseWindow() 先触发 WINDOW_CLOSE_REQUEST，交给窗口自己的 setOnCloseRequest 做"未保存"确认，未被拦截才关闭。
位置与外观坐标单位为屏幕像素，支持负值（多显示器）
getX()/getY() 是窗口左上角相对整个虚拟桌面的坐标。 centerOnScreen() 会把窗口放到它所处屏幕的可见区域中央， 多显示器时不会跑到主屏。
以当前窗口为父窗口开窗最常用：不用自己拼 parentKey
宽度/高度传 null 或 0 时使用 app.defaultWidth / app.defaultHeight 
// 父窗口自动 = 当前窗口；主窗口调用时父窗口为 null
var key = WindowApi.createChildScene('web/windowapi-demo.html', 920, 680);
var modal = WindowApi.createChildWindowScene('web/confirm.html', 480, 320);
模态窗口会阻塞父窗口的输入；WINDOW_MODAL 需要 owner（当前窗口）， 在 APPLICATION_MODAL 下所有窗口都会被阻塞。创建方法必须在 JavaFX 线程调用——前端调用天然满足。
显式指定父窗口需要把窗口挂到别的窗口下时使用
// 显式父窗口：null = 主窗口；空串 "" 不是主窗口，会导致窗口"孤儿化"
var key = WindowApi.createScene('web/windowapi-demo.html', 900, 660, null);
只有 null 表示主窗口。传空串或未知 key 时窗口仍会打开，但不会出现在任何窗口的 getChildKeys() 里，也不会随父窗口关闭——框架会打印 WARN 提示。
三种模态怎么选
方法Modality行为
createChildSceneNONE不阻塞任何窗口，父子关系仅体现在层级与随父关闭。
createChildWindowSceneWINDOW_MODAL阻塞 owner（当前窗口），但应用内其它窗口仍可操作。
createChildApplicationSceneAPPLICATION_MODAL阻塞应用内所有窗口，适合登录、全局确认等场景。
当前窗口的子窗口 数据来自 getChildKeys()
ControllerKey 标题 状态 操作
窗口关闭时框架会销毁该窗口的桥接器并通知父窗口；父窗口页面实现 $$_onChildReady(childKey)、$$_onChildClosed(childKey) 即可同步刷新。
框架回调约定
// 框架在页面加载完成后调用一次（约 1 秒后，等所有桥接器注入完成）
window['$$_apiReady'] = function () {
    log('WindowApi 已就绪');
};

// 子窗口 page 就绪时，父窗口收到
window['$$_onChildReady'] = function (childKey) {
    refreshChildren();
};

// 子窗口关闭时，父窗口收到
window['$$_onChildClosed'] = function (childKey) {
    refreshChildren();
};
跨窗口操作约定
所有跨窗口方法都以 ByControllerKey 结尾，第一个参数是目标窗口的 controllerKey。用顶部目标栏指定目标：留空表示主窗口（传 null）， 也可以从下拉框选择或粘贴子窗口 key。下面代码里的 targetKey 指的就是这个值。 
var targetKey = null;                 // null = 主窗口
var title  = WindowApi.getTitleByControllerKey(targetKey);
var width  = WindowApi.getWidthByControllerKey(targetKey);
var exists = WindowApi.hasWindow(targetKey);

WindowApi.setTitleByControllerKey(targetKey, '改个标题');
WindowApi.setSizeByControllerKey(targetKey, 1024, 720);
WindowApi.centerOnScreenByControllerKey(targetKey);
Java → 前端回调本页已注册 demoPing / demoReceive
onCallByControllerKey(key, name) 只在目标窗口调用同名 JS 函数； onCallAllStage(name) 广播到所有存活窗口； executeJsByControllerKey(key, script) 可以执行任意 JS 表达式。 回调统一用 !!window['name'] && window['name'](...) 生成，目标窗口没有该函数时静默跳过，不会报错。 
// 当前页面注册回调
window.demoPing = function () {
    console.log('收到广播，当前窗口：' + WindowApi.getKey());
};

window.demoReceive = function (payload) {
    console.log('收到参数：', payload);
};

// 父窗口触发子窗口
WindowApi.onCallByControllerKey(childKey, 'demoPing');

// 广播给所有窗口（含主窗口）
WindowApi.onCallAllStage('demoPing');

// 执行一段 JS（在目标窗口上下文里）
WindowApi.executeJsByControllerKey(childKey, "alert('hi')");
Java 侧发送回调用 ParamsUtils.onCallBack(controller, "demoReceive", "hello", 42, true)； String / Number / Boolean / null 会按原生类型传入，其它对象会序列化为 JSON 字符串， 前端需要自己 JSON.parse。
窗口生命周期
框架状态机：INSTANCE → OPENING → OPENED → CLOSING → CLOSED → DESTROYED； 初始化失败会进入 FAILED。isOpened() 为 true 时窗口才真正可交互。 
var status = WindowApi.getStatus();          // "OPENED(已打开)"
var opened = WindowApi.isOpened();           // true / false
var exists = WindowApi.hasWindow(targetKey); // 目标窗口是否仍存活

// 能走关闭确认时优先用 requestCloseWindow：
// 窗口自己的 stage.setOnCloseRequest(e -> { ... }) 可以先弹"未保存"确认，
// 并调用 e.consume() 阻止关闭。
WindowApi.requestCloseWindow();

// 强制关闭（不会触发二次确认）；关闭主窗口后应用退出
WindowApi.closeWindow();

// 关闭当前窗口的全部子窗口，返回提交关闭的数量
var n = WindowApi.closeChildWindows();
关闭窗口是延迟执行的（投递到 JavaFX 事件队列），避免在 WebView 正在执行 JS 时销毁它的上下文； 因此调用 closeWindow() 后当前脚本还能执行完。
完整方法参考与 core 中 WindowApi.java 的真实签名一一对应
返回值 Double / Boolean 在找不到窗口时为 null， 而当前窗口版本返回 double / boolean 的安全默认值。 ByControllerKey 的写方法返回 boolean，表示目标窗口是否存在。

2. 自定义子窗口控制器StageControllerFactory
@Component
public class MyStageControllerFactory implements StageControllerFactory {

    @Override
    public GenericBeanDefinition create(String key, Stage stage, BaseController parent,
                                        String url, double width, double height) {
        GenericBeanDefinition def = new GenericBeanDefinition();
        def.setBeanClass(MyChildController.class);   // 必须继承 BaseController
        def.getConstructorArgumentValues().addGenericArgumentValue(key);
        def.getConstructorArgumentValues().addGenericArgumentValue(stage);
        def.getConstructorArgumentValues().addGenericArgumentValue(parent);
        def.getPropertyValues().add("resourceUrl", url);
        def.getPropertyValues().add("width", width);
        def.getPropertyValues().add("height", height);
        return def;
    }
}
容器里出现任意自定义 StageControllerFactory 后，内置的 DefaultStageControllerFactory 自动失效，所有 WindowApi.createXxxScene 创建出来的窗口都会走你的控制器。
3. Java 调用前端方法ParamsUtils.onCallBack
// controller 可以是 ContextUtils.getController(key)，也可以是任意 BaseController
ParamsUtils.onCallBack(controller, "demoReceive", "hello", 42, true);

// 前端：
window.demoReceive = function (text, num, flag) {
    console.log(text, num, flag);   // hello 42 true
};
参数编码：String 单引号转义、Number/Boolean 保留原生类型、 null 原样传入；其它对象序列化为 JSON 字符串，前端需要 JSON.parse。回调方法不存在时静默跳过。
4. 自定义前端 APIAbstractJavaApiBridge
@Component
@Scope(ConfigurableBeanFactory.SCOPE_PROTOTYPE)   // 必须 prototype，每个窗口独立实例
public class HelloApi extends AbstractJavaApiBridge {

    public String hello(String name) {
        return "Hello, " + name + "（来自窗口 " + getKey() + "）";
    }

    public boolean isMain() {
        return getKey() == null;
    }
}

// 前端：window.HelloApi.hello('World')
命名空间默认取类名。窗口加载完成后框架会创建实例、调用 bindController(this) 绑定当前窗口并注入 window.HelloApi， 窗口关闭时自动销毁。注意不要写成单例，否则多个窗口会串台。

常见问题与踩坑点
1. 为什么 getChildKeys()[0] === 'xxx' 是 false？
JavaFX WebView 返回的 String[] 是 JS 数组，但元素是 Java String 包装对象。 统一用 String(keys[i]) 转成原始字符串，或者 keys.join(',').split(',')。
2. 主窗口的 key 是什么？为什么不能传 ""？
主窗口 getKey() 返回 null。框架里只有 null 表示主窗口； 空串 "" 和未知 key 一律当作"找不到窗口"。需要显式表示主窗口时传 null， 不要用 ""。
3. 创建窗口时宽高传 null 会怎样？
createXxxScene 的参数是 Double，传 null / 0 / 负数 都会回落到 app.defaultWidth / app.defaultHeight，不会 NPE。
4. 模态窗口为什么没有阻塞？
模态需要 owner：createWindowScene 必须传父窗口 key； createChildWindowScene 自动取当前窗口。主窗口作为 owner 时， WINDOW_MODAL 会阻塞主窗口。创建窗口本身必须在 JavaFX 线程执行（前端调用天然满足）。
5. closeWindow 和 requestCloseWindow 有什么区别？
closeWindow() 强制关闭，不触发 setOnCloseRequest； requestCloseWindow() 先发 WINDOW_CLOSE_REQUEST， 窗口可以在处理器里 event.consume() 取消关闭，未取消才兜底关闭。 关闭主窗口会让应用退出。
6. 在后台线程调用 set 方法会怎样？
写操作会自动投递到 JavaFX 线程，按顺序异步生效；但读取属性、创建/选择窗口 需要在 JavaFX 线程调用。前端 JS 调用天然都在 JavaFX 线程，可以"设置后立即读"。
7. 全屏和置顶能同时开吗？
JavaFX 对 fullScreen 与 alwaysOnTop 同时为 true 的支持因平台而异。 如果切换失败，先关闭另一个状态再试；框架会捕获并记录异常，不会中断页面。
8. 为什么页面里不能用箭头函数 / let / 模板字符串？
JavaFX 8 自带的 WebKit 538 只支持 ES5。为了兼容 JDK 8 与 JDK 17 的 openjfx 两种运行环境，示例统一使用 var、function 和字符串拼接。
9. WindowApi 安全吗？
window.WindowApi 是完整 Java 对象，JS 可以调用所有 public 方法 （包括基类的 getStage()、destroy()）。只把它注入给 随应用打包的可信 HTML；展示远程页面/用户 HTML 时请另开一个不注入桥接器的 WebView。
